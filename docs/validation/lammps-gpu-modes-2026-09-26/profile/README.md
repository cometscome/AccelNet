# H100カーネル時間による追加診断

前の実行時間比較だけでは、directの並列度向上とmoment側の効率低下を区別できなかった。
Nsight Systemsで分解すると、**moment構築が5,184→24,000原子で約10倍に増加**していた。
原子数は4.63倍、同じモデル・密度・近傍数なので、この構築処理の原子あたり時間が悪化している。
大きい系で倍率が縮む説明として、moment側の効率低下を明示する必要がある。

## 方法

- 前の測定と同じH100 NVL、実行ファイル、Ti/Oモデル、入力を使用。
- Nsight Systems 2025.5.2、`--trace=cuda --sample=none --cpuctxsw=none`。
- 192 / 5,184 / 24,000原子、direct / momentを各1回測定。
- 20 step warmup + 100 stepの既存入力。123回の各カーネル起動のうち、
  warmupと各runの初期評価を除き、添字22〜121の100起動を集計。
- 表はGPUイベント時間の算術平均、ms/step。CPU待機・転送時間を含まない。
  前の中央値による非計測器付きLoop timeとは異なる測定値。
- 計測器付き実行の最終座標・力・原子別エネルギーも元の実行と比較し、全6ケースで合格。
- 元のバイナリのままで計測。製品コードの変更はない。

## モーメント構築の効率低下

| moment側の処理 | 5,184原子 | 24,000原子 | 時間倍率 |
| --- | ---: | ---: | ---: |
| 幾何・動径・方向の累乗 | 1.325 | 3.476 | 2.62× |
| モーメント構築 | 1.232 | 12.358 | 10.03× |
| モーメントから記述子への変換 | 0.208 | 0.219 | 1.06× |
| NN・角度係数変換 | 0.116 | 0.138 | 1.19× |
| 近傍ごとの力計算 | 1.410 | 6.506 | 4.61× |
| 力・virial集計 | 0.171 | 0.452 | 2.64× |

モーメント構築は約0.238→0.515 μs/原子となり、原子あたり約2.17倍遅くなった。
一方、近傍ごとの力計算は4.61倍で、おおむね原子数に比例する。
24,000原子のmoment構築だけで約12.36 ms、非計測器付き総時間25.07 msの約半分に相当する。

| 原子数 | mode | 記述子関連合計 | NN・係数変換 | 近傍ごとの力 | 力・virial集計 | 入力変換 | 計測器付きLoop |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 192 | direct | 8.473 | 0.088 | 0.175 | 0.065 | 0.115 | 9.083 |
| 192 | moment | 1.085 | 0.093 | 0.088 | 0.065 | 0.116 | 1.635 |
| 5,184 | direct | 10.748 | 0.102 | 2.031 | 0.162 | 0.345 | 13.749 |
| 5,184 | moment | 2.765 | 0.116 | 1.410 | 0.171 | 0.345 | 5.166 |

| 24,000 | moment | 16.054 | 0.138 | 6.506 | 0.452 | 1.235 | 25.196 |

24,000原子で記述子関連合計はdirect約17.67 msに対してmoment約16.05 msと、差が小さい。
これは「moment構築の効率低下」と「directの記述子時間が原子数ほど増えない」の両方を含む。
前の説明は後者に偏っていた。momentの改善優先箇所は構築カーネルである。

## 原因について確定した範囲

`accelnet_target_kernels.f90`の126行目からのカーネルは、原子×単項式に並列化している。
角度次数6では84成分あり、各成分が同じ原子の近傍リスト・cutoff・方向の累乗を再び読む。
異なる原子を隣接するGPUスレッドで処理するので、CSRの近傍配列へのアクセスは連続しにくい。
大きい系で中間配列がキャッシュに収まりにくくなることと、この再読込の組合せが原因候補。

ただし、**キャッシュミス率やDRAM帯域が原因だとはまだ断定しない**。
Nsight Computeのハードウェアカウンタは`ERR_NVGPUCTRPERM`で取得できなかった。
GPUドライバ設定は変更していない。Nsight Systemsのイベント時間は取得できている。
両サイズでblock=128、registers/thread=48、localMemory/thread=0の同一カーネル。

次の改善候補は、原子単位のwarp/blockで近傍データを共有して複数モーメントをまとめて計算し、
近傍データの再読込を減らすこと。その前後で同じ数値テストとサイズ別速度測定を行う。
続く[診断用の比較実験](../locality/README.md)で処理順序を変えた版を実装・測定し、
構築カーネル約12倍・全体約1.82倍の改善を確認した。正式な計算コードへの採用は未実施。
