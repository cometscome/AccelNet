# moment構築・力計算の正式実装と検証 — 2026-09-26

GPU専用のFortranカーネルへ、原子ごとのモーメント構築順序と、力計算の係数事前計算・
多項式勾配の縮約を取り込んだ。CPU評価コード・API・コンパイラフラグは変更していない。
`auto`でmomentを選んだ行と、明示的な`moment`の両方に適用される。

## 変更

1. 構築カーネルを原子→モーメント成分の順序でGPUへ割り当てる。
   原子ごとの近傍幾何・方向累乗を隣接する仕事で再利用する。
2. NN入力勾配を得た後、各中心原子でモーメントの力用係数を一度だけ計算する。
   以後不要となるraw momentsの領域を再利用し、新たな常駐配列は増やさない。
3. 各近傍で多項式の値と方向についての勾配を縮約してから、
   cutoffの微分・方向の接平面への射影を適用する。自己ペア補正も先に合算する。
   これまで各成分で行っていた射影・除算などをまとめる。

原子i・単項式αの係数は、次数qのNN由来勾配δと多重度mを用いて
`C0=m*δ0*M0`, `C1=m*δ1*M1`。近傍のspecies weightをs、単位方向をuとすると
`P(u)=Σα (C0α+s*C1α) u^α` を計算する。
力の角度寄与は `f'(r)*u*P + f(r)/r*(∇P-u*(u·∇P)) - f(r)*f'(r)*Q*u`、
`Q=Σq(δ0q+s²*δ1q)`。δは既存の負のエネルギー微分を含む。
式は既存の和を分配・縮約したもので、精度を下げる近似は導入していない。
浮動小数点の演算順序は変わるので、bitwise一致は要件としない。

各evaluateで構築→記述子→NN→係数→力の順に進み、次のevaluateでraw momentsを再構築する。
直接法の行では係数への上書きを行わない。異なる元素がdirect/momentを同時に使い、
その割当を同じworkspaceで入れ替える数値・有限差分テストを追加した。

## 検証

- 処理順序変更だけの段階: H100 GPU CTest 19/19。
- 最終版: H100とBlackwellでそれぞれGPU CTest 19/19。
  syntheticのauto/direct/momentは各61ケース、実Ti/Oは各18ケース。
  全cutoff、activation、Chebyshev 0/1/10、次数0/8、異なるNN形状、空・部分行・
  並べ替え・加算出力・workspace再利用、座標/ひずみ有限差分を含む。
- LAMMPS: H100で56比較、Blackwell 2 GPUで16比較、計72比較が合格。
  CPU 1 rank基準、auto/moment、neigh no/yes/hybrid、1/2 rank、三斜晶、空rank、
  20 step NVE、H100側は5 step間隔の近傍更新と原子移動も含む。
- 性能測定の全63実行でもGPU direct基準の力・原子別エネルギー・座標、
  thermoのエネルギー・virial圧力6成分の比較が合格。
- LAMMPS 2 rankで24→192原子の再確保とclear後のモデル再読込も合格。
- H100 Compute Sanitizer memcheck: forced-moment synthetic全61ケースで0 errors。
  `--leak-check no`で実行。NVHPCランタイムの終了時プール解放を保証する検査ではない。
- GNU Fortranによるoptional target libraryのコンパイルも合格。
  GNUビルドはhost OpenMP構成であり、GNUによるGPU実行は未検証。
- CPU数値テスト42/42、CPU性能ラベルのテスト2/2（合計44/44）。
  CPU速度ゲートは変更前CPU baselineとの12ケース・7回の対比較、許容低下10%。
  全ケース合格、candidate/baseline比0.977〜1.014、数値差0。

LAMMPS CPU基準72比較の最大力差: 6.74e-14 eV/Å。

GPU batch比較は`atol=2e-10, rtol=2e-10`、LAMMPS原子配列は`atol=2e-8, rtol=2e-9`、
thermoは`atol=2e-5, rtol=2e-9`。詳細な誤差・全sample・CPU速度比は各JSONに保存した。
GPU性能測定中は他の検証ジョブを同時に実行せず、CPU速度ゲートも検証ジョブ終了後に実行した。
もう1枚のH100は他の利用者が使用しており、ホスト全体は専有していない。

ビルドと入力は[利用手順](../../lammps-gpu.md)のまま。

今回は、検証済みの処理順序変更と力計算の共通部分の事前計算・縮約を正式化した。
幾何・動径計算の近傍方向の協調並列化、角度専用近傍リスト、CSR offsetの並列scan、
多項式のHorner評価はまだ導入していない。次の大きな対象は幾何処理3.47 msと残る力計算3.37 ms。
GPU専用処理の変更に限定し、CPUの既存性能と複数GPUへの移植性を引き続き検証する。
